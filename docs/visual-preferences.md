# 个人视觉偏好规范

这是一份持续演化的偏好档案，用于个人主页、作品页面及其他视觉设计。它描述的是“什么更像我”，而不是一套必须机械套用的品牌规范。

## 1. 解释优先级

发生冲突时，按以下顺序判断：

1. 用户最新的明确表述；
2. 本文中标记为“已确认”的规则；
3. 从参考图归纳出的“暂定倾向”；
4. 单张参考图中的局部元素。

参考图只证明其中某些视觉特征受到偏爱，不代表图片的所有颜色、角色、构图或情绪都应复制到设计中。标记为“高权重”的图片可以较大程度影响对应设计分支的整体语言，仍不要求逐项复刻。

## 2. 核心定位

### 2.1 已确认

- **基调：**偏好深色界面。
- **浅色方案：**浅色方案与深色方案具有同等级别的代码地位。它以深色方案为结构与设计基准，不承担独立于深色方案的创新；进行色彩、对比度和质感适配时，可以较大程度参考 `VP-IMG-011`。
- **强调色：**深色方案使用 `#00D3FF`，浅色方案使用语义对应且对比更清楚的 `#005F73`。强调色用于交互、焦点、当前状态或少量结构线，不默认铺满整个页面。
- **主题一致性：**深色和浅色主题中的内容、组件、功能、交互状态与信息层级应严格一一对应。主题切换只改变视觉表达，不增删可读内容或可用能力。
- **自我呈现：**不希望被包装成“充满活力、野心勃勃的学生开发者”。
- **ACG 内容：**以初音未来（Miku）作为 ACG 设计语言的核心，在章节层级进行点缀。具体使用素材由用户后续寻找与确认。
- **新意：**在意的是设计具有新意，而不是固定采用某一种“新奇”形式。不同页面可以使用差异明显的视觉手法，前提是它们与内容有关、表达清楚，并符合其他已确认规则。

### 2.2 文案与人格气质

推荐的表达方向：克制、冷静、诚实、亲切，有明确审美但不过度自我营销。视觉可以偏冷，文案仍应让读者感到自己被看见、被邀请进入内容。语气可以保留私人性和观察感，同时维持对读者的关注；亲切不等于过度热情。

句式应以清楚的直述为主，多使用自然的并列、递进和因果关系。减少为了制造机智感、力度或“高级感”而使用的转折句式，尤其避免反复套用“不是……而是……”“虽然……但是……”“并非……只是……”等结构。真正存在对照关系时仍可使用转折，不把它当作默认节奏。

应避免：

- 热血式成长叙事；
- “年轻、充满激情、渴望改变世界”等模板化学生开发者话术；
- 用密集口号、夸张数字或强行动号召制造进取感；
- 把个人主页写成招聘广告或创业项目落地页。
- 只顾表达自我、缺乏读者意识的封闭式独白；
- 密集使用转折制造刻意的反差感。

## 3. 视觉方向

### 3.1 已确认规则

| 项目 | 规则 |
| --- | --- |
| 页面基底 | 深色优先；浅色方案具有同等代码地位，以深色方案为设计基准并参考 `VP-IMG-011` 进行适配 |
| 关键强调色 | 深色方案使用 `#00D3FF`；浅色方案使用 `#005F73` |
| 主题对应 | 深浅主题的内容、元素、功能、状态和层级严格一一对应 |
| ACG 元素 | 以 Miku 为核心设计语言；用于章节级点缀；素材待用户确认 |
| 整体气质 | 不服务于“活力、野心、学生开发者”人设 |
| 科技感 | 减少“炫酷科技感”的使用，技术元素服从内容与功能 |
| 落地感 | 偏好脚踏实地、具体、可信的呈现 |
| 新意 | 追求新意本身，不固定新意必须采用的形式 |

### 3.2 从当前参考图得到的暂定倾向

以下内容是第一轮归纳，后续可以被新的文字说明或图片直接修正：

- **冷色与有限暖色对照：**青、蓝、蓝灰占主导，黄色、红色或肤色常作为局部对照。
- **低饱和与高亮点并存：**不是持续高饱和，而是在雾感、灰度或暗部中保留少量清晰亮色。
- **克制的人物情绪：**人物多为安静、淡漠、若有所思或略带距离感的状态，而非大幅度笑容和外放姿态。
- **层叠式视觉叙事：**窗口、档案、照片墙、拉链边界、拆解零件、前景遮挡等元素能形成“信息层”和空间深度。
- **技术视觉只作为局部语言：**旧式桌面界面、机械拆解和媒介拼贴可以偶尔出现，用于表达具体内容或个人兴趣，不承担整站的“炫酷”包装。
- **留白与密度都可用：**既接受大面积留白与水墨式线条，也接受高密度拼贴；关键是画面有明确视觉中心，不是均匀堆满组件。
- **ACG 元素适合成为构图主体或叙事线索：**不宜只作为随手贴上的小贴纸。
- **落地感优先：**真实内容、具体经历、清楚结构和可理解的交互，比抽象的未来主义氛围更重要。
- **新意可以改变形式：**Miku 参考图之间存在明显风格差异，这种差异本身符合偏好；无需把新意收敛为固定的拼贴、复古界面、水墨或其他单一模板。

### 3.3 暂定设计词汇

`dark` · `cyan accent` · `cool-toned visual` · `warm copy` · `restrained` · `approachable` · `grounded` · `quiet` · `layered` · `editorial` · `cinematic` · `ACG-aware`

这些关键词用于沟通方向，不要求每个设计同时满足全部词汇。

## 4. 网页应用原则

### 主题一一对应

- 深色与浅色主题共享同一份信息架构、正文、媒体、组件、操作入口和交互状态。
- 两套主题在代码中都是一级实现，接受同等程度的维护、测试和无障碍检查；浅色方案不作为简化版或兼容补丁存在。
- 深色方案提供主要结构、构图与交互创新，浅色方案尽量忠实映射这些决定，再调整色彩、对比度、阴影和纹理。
- 每个元素在另一主题中都有角色、位置和含义相同的对应元素，不设置主题限定内容。
- 主题切换后保留当前页面、滚动位置、展开状态、筛选条件和用户输入，避免让切换主题成为一次页面重置。
- 颜色、阴影、边框、纹理和透明度可以分别适配。它们应通过语义化设计变量成对映射，例如 `accent-dark` 与 `accent-light` 共同承担“强调”角色。
- 同一语义可以使用不同色值。严格对应指内容和作用一致，不要求两个主题机械复用同一个十六进制颜色。
- 强调色采用固定映射：`dark → #00D3FF`，`light → #005F73`。
- 验收时逐项对照两个主题，检查元素数量、文字、媒体、功能、状态和阅读顺序是否一致。

### 推荐

- 以深色中性色建立大面积背景，让 `#00D3FF` 只标记交互、焦点、当前状态或少量结构线。
- 浅色方案使用冷灰或带轻微蓝紫倾向的低对比背景，以大面积留白承托柔和的粉、蓝、青、黄渐变；可加入细颗粒纹理和克制的黑色文字。
- 用不对称构图、裁切、遮挡或分层制造个人感，但正文阅读路径仍需清楚。
- Miku 图像或相关视觉语言用于章节标题、章节过场、局部背景或同等级别的点缀，不扩张为持续覆盖整页的角色陈列；实际素材应结合授权、裁切适配和页面性能决定。
- 人物图像优先选择情绪克制、构图鲜明的画面；页面文案应与其安静气质协调。
- 先展示真实项目、经历、兴趣和作品，再决定是否需要技术装饰。终端、旧桌面窗口、线框或拆解图只在与内容有关时少量使用。
- 用明确名称、具体事实和自然语言建立可信度；让读者容易理解页面在讲什么，以及这些内容为什么值得展示。

### 避免

- 大面积明亮青色或全页霓虹导致视觉疲劳；
- 把 ACG 内容堆成无层级的角色墙；
- 通用“赛博朋克”“电竞 RGB”套件替代具体审美判断；
- 为了显得专业或先进而堆叠网格、扫描线、HUD、发光边框、终端文字和无意义数据；
- 用抽象科技口号掩盖内容不足，或让形式抢走真实经历与作品的重点；
- 把浅色方案理解成高亮白底、糖果色组件或持续高饱和渐变；
- 通过隐藏图片、删减文字、移除功能或改变信息顺序来简化其中一个主题；
- 未确认版权和使用许可就把参考图直接发布为线上页面资产。

## 7. 维护约定

### 版本格式

- 风格版本使用 `YYYY.MM.DD.N`，分别表示年、月、日和当日第 `N` 次修改，例如 `2026.08.08.1`。
- 每次改变偏好、解释边界、设计原则或参考图集合时，都递增版本号并更新 `last_updated`。
- 跨日期修改时，日期替换为当天日期，末位序号从 `1` 重新开始。
- `schema_version` 只表示文档数据结构版本，不代替风格版本。

### 新增一条明确偏好

直接加入“已确认”部分；如果它推翻暂定倾向，同时修改或删除旧条目，不保留互相冲突的现行规则。

### 新增一张参考图

1. 将图片复制到 `docs/visual-preferences/`，使用 ASCII 小写文件名；
2. 在“参考图库”末尾新增 `VP-IMG-xxx` 条目；
3. 至少填写文件、尺寸、角色/主题、偏好范围和不应直接推断；属于画面设计参考时填写“可借鉴”，仅代表角色偏好时填写“画面记录”；
4. 仅当多张图片反复支持同一特征时，才把它提升为“暂定倾向”。

### 删除一张参考图

删除对应 `VP-IMG-xxx` 小节和图片文件。编号无需重排，以免旧讨论中的引用失效。
